# CampusRide

Source of truth: supplied maquette_ecrans.png and project brief from OneDrive_1_23-10-2026.zip. French student carpooling MVP; teal/white, compact mobile forms, five persistent navigation entries, route cards and explicit confirmation modals. No invented sample trips. Payment is agreed directly between students.

Palette: primary #09967d; dark primary #087966; ink #19232f; panel #f5f6f8; border #e7eaee. Segoe UI/system sans. Card radius 10px. Buttons and fields at least 44px high. The Appsmith canvas uses fluid width. Forms remain readable at 560px; signed-in content uses up to 1000px. The widget grows with its content so the host page owns scrolling. Keyboard focus is visible; motion respects reduced-motion preferences.

Screen families: landing/authentication; dashboard/search/results/detail; publish/manage; history/reviews; profile/preferences; messages/notifications. Empty, pending, failed and successful states use actual backend outcomes.

Implementation: Appsmith Custom1 React widget, fixed prepared Query1 bridge, private PostgreSQL campusride API. Password hashes and session hashes remain in the private schema. The widget receives only the signed-in user's snapshot. Sessions are in-memory and require login after a reload. Existing public tables are extended without deletion.

Responsive layout: `widget.css` is the shared runtime owner. The iframe uses natural content height and no viewport-height CSS units. At widths up to 900px, `useMobileViewportBars` in `widget.jsx` anchors the header and the combined composer/navigation dock within the visible portion of the growing iframe. A dynamic coverage floor uses the maximum native application height and available screen height seen during the session; only a physical mobile screen (both dimensions at most 1024px) uses its longest dimension to cover rotation. It never derives the floor from the iframe/body height, preventing auto-height feedback and cumulative growth. Short pages may contain extra blank scroll space to retain this coverage. At 540px and below, inputs use 16px type and compact gutters; at 420px and below, paired form fields and search filters stack. Grid tracks use `minmax(0,1fr)`; long names, locations and actions wrap. The five navigation entries remain available with touch targets at least 44px tall. Desktop max-widths limit reading length, never the mobile canvas width.

Viewport bar ownership: the Appsmith host remains the sole content scroll owner. An implicit-root IntersectionObserver measures only `.phone` inside the sandbox; re-observation at most about 30 times per second refreshes coordinates when the intersection ratio stays constant during host scrolling. No parent DOM, sandbox relaxation, custom parent messages or API calls are used. Bar positions are clamped to the phone bounds; stable header/dock spacers preserve content flow. ResizeObserver refreshes bar sizes, CSS writes occur only for meaningful changes, and observers/listeners/animation frames are cleaned up or suspended when hidden. Wider layouts retain the natural desktop flow.

Keyboard scope: desktop input focus keeps both bars anchored. On coarse touch screens without hover, editable focus releases the footer into normal document flow and asks the browser to reveal the field. This fallback avoids pretending that the sandbox can read the parent's keyboard-adjusted visual viewport. Real-device keyboard behavior remains to be verified; desktop resizing is not evidence of it.

Appsmith landscape clearance: between 700px and 900px of widget width, the navigation dock reserves 48px below its controls for the native bottom-right “Built on Appsmith” badge. ResizeObserver includes this padding in the measured dock height; narrower portrait widths receive no additional reserve. The shared `widget.css` media rule owns this value.
